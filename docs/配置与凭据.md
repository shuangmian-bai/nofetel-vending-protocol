# 配置与凭据（唯一事实源）

本文件定义「什么进 `.env`、什么必须进密钥库」。改配置项先改这里。

## 一、两个文件

| 文件 | 入库 | 内容 | 说明 |
|---|---|---|---|
| `config/.env.example` | 是 | 全部配置项的**占位与说明** | 模板，值留空或给默认 |
| `config/.env` | 否（gitignore） | 本机实值 | 由模板复制后填写 |

**在无 POSIX 权限位的磁盘（NTFS/exFAT）上，`chmod 600` 不生效**，实测权限恒为 777。
用 `stat -c %a <文件>` 复查：不是 600 就当它没有任何保护。
因此 `.env` 的安全底线不是文件权限，而是**里面不放凭据**。

## 二、配置分级（硬性）

| 级别 | 内容 | 放哪 | 理由 |
|---|---|---|---|
| 设备标识 | `NOFETEL_DEVID` | `.env` / 环境变量 / `--dev-id` | 每台机器不同，可注入；泄露只暴露"这台柜子"，不构成身份 |
| 客户端常量 | `NOFETEL_APP_ID`、`NOFETEL_CLIENT_VERSION`、`NOFETEL_BASE_URL` | `.env` | 公开信息，抓包即得 |
| 门禁阈值 | `NOFETEL_MAX_ORDER_AMOUNT` | `.env` | 安全参数，非机密 |
| 轮询/BLE 参数 | `NOFETEL_PAY_POLL_*`、`NOFETEL_BLE_*` | `.env` | 协议常量 |
| **身份凭据** | `openId`、`sessionKey` | **仅密钥库** | 等价账号口令，见下 |
| **开柜指令** | `payCode` | **不落盘**，只在内存与蓝牙帧里 | 服务端签发，一次性 |

### 为什么 openId 不能进 .env

- 服务端把它当唯一身份（`user-id` 头），无签名、无二次校验；
- `.env` 在这块盘上对所有本机用户可读（777 不可改）；
- 一旦写入 `.env`，它就会随 `docker cp`/打包/截图等日常动作泄漏。

正确做法：用密钥库工具把值注入子进程环境变量 `VAULT_NOFETEL_OPENID`
（作者环境为 `vault use nofetel_openid -- <命令>`），值不进 argv、不进日志、不进文件。

## 三、设备 ID 的三种注入方式

优先级：**命令行 > 环境变量 > `.env`**

```bash
# 1) 配置文件（最常用）
NOFETEL_DEVID=<DEVICE_ID>      # config/.env

# 2) 环境变量（临时切设备，不改文件）
NOFETEL_DEVID=<DEVICE_ID> .venv/bin/python main.py info

# 3) 命令行（最高优先，适合脚本循环多台）
.venv/bin/python main.py --dev-id <DEVICE_ID> info
```

三者都缺时报错会同时列出这三种写法（`pyapp/api/client.py::NoftelConfig.from_env`）。

## 四、换一台设备时要改什么

只有一处：`NOFETEL_DEVID`。机型相关差异（货道数、是否密码柜、BLE 特征）
全部由 `/front/dev/getModelConfig` 运行时取回，不需要改配置。
例外的机型：若 `hasPwd=1`（密码柜），BLE 特征可能不同，需改 `NOFETEL_BLE_*`。

## 五、常见错误

| 现象 | 原因 | 处理 |
|---|---|---|
| `设备未入库:XXXX` | devId 写错或设备不存在 | 核对二维码上的印字 |
| `缺少设备主键 devId` | 三种方式都没给 | 按提示任选一种 |
| `未检测到 VAULT_NOFETEL_OPENID` | 忘了注入凭据 | 设置环境变量后重跑；写操作会被直接拒绝 |
